# 15 论文交付工作台升级规划（Thesis Workbench Upgrade Plan）

## 1. 背景与目标
当前系统已具备订单、支付、论文任务、AI 生成、导出任务、后台管理等基础能力，下一阶段目标是从“论文生成与下载”升级为“论文交付工作台”。升级后的平台不只生成一份可下载文档，而是围绕学校/专业上下文、论文阶段、Skill 编排、在线合稿、版本记录、格式模板与合规留痕，形成可持续迭代的交付生产体系。

本规划仅作为后续开发依据，不在本次直接大规模改动业务代码；后续每个 Issue 必须基于 `dev` 创建独立分支，小步提交，并在 Trae 本地环境完成验证。

## 2. 产品边界与合规原则
### 2.1 产品定位
- 平台定位为“论文辅导与写作辅助工作台”，帮助学生梳理选题、结构、表达、格式、引用与导师意见修改。
- 平台产物应作为学习辅导材料、写作参考、格式辅助与修改建议，不承诺替代学生独立完成学术成果。
- 平台必须保留学生输入、AI 辅助记录、导师意见、修改记录、引用核验提示和导出记录，便于用户自查与合规追溯。

### 2.2 禁止能力
- 不伪造实验数据、调研数据、访谈记录、问卷样本、统计结论。
- 不伪造引用、DOI、期刊、作者、页码、标准号或不存在的文献来源。
- 不提供绕过学校审查、规避导师审核、规避查重系统的承诺或暗示。
- 不输出“保证通过”“保证查重率”等不可控结果承诺。

### 2.3 必须提示
- 原创性提示：学生需基于自身研究、课程要求和导师意见进行最终确认。
- 引用核验提示：所有参考文献需由用户自行检索核验，系统只做格式与线索辅助。
- AI 辅助声明：导出文档可附带 AI 辅助说明或留存内部审计记录。
- 导师意见修改记录：每次依据导师意见产生的修改必须记录修改前、修改后、修改原因、操作者与时间。

## 3. 升级范围概览
| 能力域 | 目标 | 首期边界 | 不做事项 |
|---|---|---|---|
| 学术基础数据 | 支撑学校、学院、专业、学历层次、论文类型上下文 | 建表、后台维护、学生/后台选择、Task 关联、AI 上下文读取 | 不一次性接入全国完整官方库 |
| 论文 Skill 中心 | 用可版本化 Skill 管理各阶段生成/检查策略 | Skill CRUD、版本、启停、适用范围、输入/输出 schema、质量规则、模型配置 | 不直接照搬 Nature 论文内容 |
| 文档工作台 | 阶段文档在线查看、章节编辑、合稿、版本记录 | 任务文档、章节树、阶段版本、导出入口、修改记录 | 不做多人实时协同编辑 |
| 格式模板引擎 | 支持学校/专业/阶段/自定义模板导出 | 模板元数据、格式规则 JSON、模板选择优先级、导出任务参数 | 不承诺还原所有 Word 复杂排版 |
| 合规留痕 | 降低学术诚信与引用风险 | 合规提示、引用核验状态、AI 辅助记录、导师意见修改记录 | 不进行法律或学校政策最终裁定 |

## 4. 学术基础数据能力
### 4.1 数据层级
- `Province`：省份/直辖市/自治区。
- `City`：城市，关联省份。
- `University`：高校，关联省份、城市，可维护学校类型、学校代码、状态。
- `College`：学院/系，关联高校。
- `DisciplineCategory`：学科门类，如工学、管理学、文学。
- `DisciplineFirstLevel`：一级学科，关联学科门类。
- `Major`：二级学科/专业，关联一级学科，可选关联学校或作为通用专业库。
- `UniversityMajor`：高校开设专业，用于解决“同名专业在不同高校配置不同模板/要求”的问题。

### 4.2 任务上下文
论文任务创建或补全时必须记录：
- 学校、学院、专业、学科门类、一级学科、学历层次、论文类型。
- 研究方向、导师格式要求、学校模板、专业模板、用户补充格式说明。
- 这些字段进入 AI 生成上下文，但不得影响订单、支付、退款的既有结算流程。

### 4.3 To C / To B / 管理三方影响
- 学生视角：创建任务或进入工作台时，可选择学校、专业、学历层次、论文类型，并看到这些上下文会影响选题、大纲、正文与导出格式。
- 机构视角：代下单/推单时可替学生补充学校与专业，减少后续补资料返工。
- 管理视角：后台可维护基础数据、批量导入、停用错误数据，并在任务详情中补全或纠偏。

## 5. 论文 Skill 中心
### 5.1 Skill 定义
Skill 是对某个论文阶段或质量检查动作的可配置能力单元，包括：
- 基础信息：`code`、`name`、`description`、`stage`、`status`、`version`。
- 适用范围：学历层次、本科/专升本/高职/硕士、论文类型、学科门类、专业、学校、阶段。
- 输入 schema：任务上下文、用户输入、导师意见、引用列表、章节内容、格式要求。
- 输出 schema：题目列表、开题报告结构、大纲树、章节正文、修改建议、检查报告、导出配置。
- 质量检查规则：字数、结构完整度、引用占位、禁止承诺、敏感声明、格式校验、导师意见覆盖率。
- 模型配置：模型、温度、最大 token、系统提示、重试策略、扣费策略、灰度比例。

### 5.2 首期 Skill 分类
| Skill 阶段 | 场景 | 典型输出 |
|---|---|---|
| TOPIC | 选题/题目优化 | 题目候选、选题理由、研究边界 |
| OPENING | 开题报告 | 研究背景、意义、方法、计划、参考文献线索 |
| OUTLINE | 大纲 | 章节树、章节目标、字数建议 |
| DRAFT | 正文初稿 | 分章节正文、引用占位、待核验项 |
| REVISION | 导师意见修改 | 修改清单、差异说明、版本记录 |
| REDUCTION | 表达降重辅助 | 改写建议、重复风险提示，不承诺查重率 |
| FORMAT_CHECK | 格式检查 | 封面/目录/标题/页眉页脚/参考文献检查报告 |
| REFERENCES | 参考文献辅助 | 文献格式、核验状态、缺失字段提醒 |
| DEFENSE_PPT | 答辩 PPT | 页结构、讲稿提纲、图表建议 |

### 5.3 Skill 编排原则
- Skill 不直接替代 Prompt 管理；Prompt 可作为 Skill 版本的组成部分或底层资产。
- Skill 运行必须写入 `AiGenerationRun` 或新增 `SkillRun`，记录输入摘要、输出摘要、模型配置、质量检查结果与费用。
- Skill 选择优先级建议：任务指定 Skill 版本 > 学校/专业配置 > 学历/论文类型默认 Skill > 系统默认 Skill。
- Skill 停用后不得影响历史任务查看和历史导出；历史运行继续引用当时版本快照。

## 6. 论文文档工作台
### 6.1 工作台能力
- 阶段文档查看：题目、开题、大纲、初稿、终稿、答辩 PPT。
- 在线合稿：根据大纲与章节产物合并为任务级文档。
- 章节编辑：章节标题、正文、备注、锁定状态、AI 生成状态。
- 版本记录：每次生成、人工编辑、导师意见修改、格式应用、导出前快照均形成版本。
- 阶段导出：题目、开题、大纲、初稿、终稿可分别导出。
- 模板导出：通用模板、学校模板、专业模板、自定义模板。

### 6.2 版本策略
- `ThesisDocument` 表示任务维度或阶段维度文档。
- `ThesisDocumentVersion` 保存不可变快照，包含版本号、来源、操作者、章节树快照和合规提示状态。
- `ThesisChapter` 保存当前可编辑章节内容；版本快照用于回滚与审计。
- 导出任务必须引用具体版本 ID，避免导出过程中内容被编辑导致结果不一致。

### 6.3 UI 目标页面
- 学生端：`/tasks/[id]/workbench`，查看阶段、编辑授权章节、提交导师意见、导出。
- 机构端：`/agency/tasks/[id]/workbench`，查看受授权任务、补充学生/学校信息、提交协同备注。
- 管理端：`/admin/tasks/[id]/workbench`，编辑/纠偏/质检/模板选择/代导出。

## 7. 格式模板引擎
### 7.1 模板类型
- 通用模板：系统默认，兜底适用于无学校/专业配置的任务。
- 学校模板：按高校配置封面、标题、目录、页眉页脚、页码、参考文献样式。
- 专业模板：覆盖学校模板中的部分规则，如章节结构、图表规范、引用风格。
- 自定义模板：用户上传或管理员配置的模板，需通过安全解析与白名单规则。

### 7.2 模板优先级
建议导出时按如下顺序解析：
1. 用户本次导出指定模板。
2. 任务绑定的专业模板。
3. 任务绑定的学校阶段模板。
4. 学历层次 + 论文类型默认模板。
5. 系统通用模板。

### 7.3 格式要求解析
用户可输入自然语言格式要求，例如“一级标题黑体三号居中，正文宋体小四，参考文献 GB/T 7714”。系统将解析为结构化 `formatRequirementJson`，并在导出前展示待确认摘要。无法可靠解析的规则必须标记为“需人工确认”，不得静默应用。

## 8. 后端模块建议
- `academic-data`：省市高校学院专业与学科目录维护。
- `thesis-skill`：Skill、版本、适用范围、质量规则、运行记录。
- `thesis-workbench`：任务文档、章节、版本、导师意见、合规提示。
- `format-template`：格式模板、模板绑定、格式解析、导出参数编排。
- 现有 `task`、`outline`、`opening-report`、`writing`、`reference`、`export` 模块保持兼容，通过服务层逐步接入工作台。

## 9. 分阶段实施路线
### Phase 0：规划与契约
- 完成本文档、功能架构、数据模型、接口设计、开发计划与验收清单。
- 不改 Prisma schema 与业务代码。

### Phase 1：学术基础数据
- 新增 Prisma 数据模型与 migration。
- 后台 CRUD 与批量导入。
- 学生/机构/后台创建任务时选择学校、专业、学历层次、论文类型。
- AI 生成上下文增加学术信息快照。

### Phase 2：Skill 中心 MVP
- 新增 Skill 与 SkillVersion 管理。
- 支持 TOPIC、OPENING、OUTLINE、DRAFT、REVISION 首批 Skill。
- 接入质量检查规则与 SkillRun 记录。

### Phase 3：文档工作台 MVP
- 新增 ThesisDocument、ThesisChapter、ThesisDocumentVersion。
- 学生端/管理端工作台页面。
- 阶段文档查看、章节编辑、版本记录、导师意见修改记录。

### Phase 4：格式模板与导出升级
- 新增 FormatTemplate 与模板绑定。
- 导出任务支持阶段、模板、格式要求解析、版本快照。
- 管理端可配置高校/专业/阶段模板。

### Phase 5：合规与运营闭环
- 增加原创性提示、引用核验提示、AI 辅助声明配置。
- 后台质检看板：引用待核验、导师意见未覆盖、格式检查失败、Skill 失败率。
- 完善审计日志、告警和回滚预案。

## 10. 后续开发约束
- 不破坏现有支付、订单、任务、导出功能；导出升级必须保留旧接口兼容路径或提供迁移说明。
- 涉及接口变更必须同步更新 `docs/06-api-design.md`。
- 涉及数据模型变更必须同步更新 `docs/05-data-model.md` 与 Prisma migration 说明。
- 涉及 To B 机构链路必须说明机构视角、学生视角、管理视角三方影响。
- 每个 Issue 独立分支、独立 PR、明确本地 Trae 验证步骤。
