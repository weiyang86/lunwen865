# 02 用户角色与流程（User Roles & Flows）

## 1. 角色定义
- USER：普通学生用户
- VIP：高级学生用户
- AGENCY_STAFF：合作机构人员（推单/代下单）
- TUTOR：导师/写手
- ADMIN：管理员
- SUPER_ADMIN：超级管理员

## 2. 权限边界（建议）
- USER/VIP：查看与管理自己的订单、任务与导出。
- AGENCY_STAFF：代下单、查看所属机构订单/任务进度、提交协同备注。
- TUTOR：查看被分配任务，提交阶段产出（题目、开题、正文、修改稿）。
- ADMIN：管理订单、任务、用户、商品、退款、任务分配。
- SUPER_ADMIN：具备全局配置、权限管理与高危操作权限。

## 3. 核心流程
### 3.1 学生自助下单流程（To C）
注册/登录 → 选择商品 → 提交订单 → 支付成功 → 创建/绑定任务 → 分阶段交付 → 修改 → 完成。

### 3.2 机构推单/代下单流程（To B）
机构登录 → 创建线索或代下单 → 支付确认（机构或学生）→ 进入任务池 → 管理员指派写手/导师 → 写手执行生成/交付 → 管理员回传交付物给机构 → 完成。

### 3.3 任务生产流程（统一）
INIT → TOPIC_* → OPENING_* → OUTLINE_* → WRITING → MERGING/FORMATTING → REVIEW/REVISION → DONE。

### 3.4 售后流程
退款申请 → 审核（同意/拒绝）→ 渠道退款结果回调 → 状态同步。

## 4. 管理操作流程
- 任务分配：管理员指定 assignee（写手/导师）。
- 状态纠偏：管理员带理由修改任务状态。
- 订单关联：将历史订单绑定到任务。
- 机构协同：管理员可查看机构侧备注与交付反馈。
- 任务池分流：后台任务管理拆分为「任务管理（散客）」与「任务管理（机构）」两类视图；散客任务来源为学生自助下单，机构任务来源为机构代下单，主要用于指派写手与交付。

## 5. 需要人工确认
- AGENCY_STAFF 是否可查看完整正文，还是仅查看里程碑状态。
- TUTOR 是否可以直接修改任务状态，还是仅提交产出待审核。
- 机构代下单时支付主体与发票主体规则。

## Task-UX-01 学生任务四阶段流程
1. 论文内容生成：学生按选题、开题、大纲、摘要、正文节点生成阶段素材。
2. 合稿与格式：学生将阶段素材导入论文文档，完成章节编辑、导师意见记录和格式准备。
3. 在线 Word 精修：学生在生成 DOCX 后进入在线 Word 精修入口，首期展示说明占位，后续接入在线编辑器。
4. 最终交付：学生下载最终版本；若后续存在在线 Word 精修版本，则最终交付优先使用最新 Word 文件版本。

### 三方影响
- 学生视角：任务列表主入口为“进入论文任务”，次入口为“继续生成”，进入后可通过四阶段导航理解当前交付路径。
- 机构视角：机构协同仍以任务进度和交付物为准，本次仅调整学生端任务内入口命名，不改变机构代下单、推单或支付流程。
- 管理视角：后台订单、支付、任务状态和导出记录不变；管理人员在沟通时应使用“论文内容生成”和“合稿与格式”新命名。
