# 00 一期市场 MVP 产品基线

> 当前有效性：本文档是本轮产品方向纠偏后的**当前有效产品基线**。若根目录旧文档与本文冲突，以 `docs/01-product/` 下本轮基线文档为准。

## 1. 产品当前定位

**论文通是一款面向学生用户的 AI 论文初稿生成与交付工具，用户付费后可生成论文内容、合稿调整、导出可编辑 Word，并在需要时提交人工论文辅导服务。**

一期市场发行版不再把“论文全生命周期协同平台”“机构端批量交付系统”“复杂写手任务平台”作为主线，而是优先验证学生用户愿不愿意为“AI 初稿生成 + Word 导出 + 必要时人工辅导”付费。

## 2. 一期市场 MVP 目标

1. 让新用户能从首页/落地页理解产品价值，并完成注册登录。
2. 让学生用户能输入论文要求或选择论文类型，使用额度生成论文初稿内容。
3. 让用户能保存生成结果，进行轻量合稿与格式调整。
4. 让用户能导出可编辑 DOCX / Word 文件。
5. 让有进一步诉求的用户能提交人工论文辅导服务申请，并由后台人工处理。
6. 在上线前保证支付、额度扣减、订单状态、生成失败处理和导出可用性具备基础可靠性。

## 3. 目标用户

| 用户类型 | 一期定义 | 核心需求 |
|---|---|---|
| 游客 | 未登录访问首页/落地页的潜在用户 | 快速理解产品能否帮助自己生成论文初稿，看到价格/能力/合规边界。 |
| 学生用户 | 已注册登录但未付费或额度不足的用户 | 输入论文要求、查看生成入口、理解付费后能获得什么。 |
| 付费用户 | 已充值或拥有可用脑细胞/额度的学生用户 | 生成内容、保存结果、合稿调整、导出 Word、必要时申请人工服务。 |
| 平台管理员 / 运营人员 | 负责后台查看订单、支付、用户和服务需求的内部人员 | 处理基础异常、查看用户服务申请、跟进订单和额度问题。 |
| 人工服务处理人员 | 负责人工论文辅导服务需求处理的内部人员 | 接收用户申请、查看需求、更新处理状态、回传处理结果。 |

## 4. 付费理由

用户愿意付费的理由应集中在直接、可感知、可交付的价值上：

1. **节省启动成本**：从空白论文要求快速获得初稿结构和内容。
2. **降低格式整理成本**：生成后可进入合稿与格式调整，并导出可编辑 Word。
3. **结果可保存可复用**：生成内容不是一次性弹窗，而是进入“我的论文 / 我的任务”。
4. **失败有兜底**：生成失败、额度扣减异常、支付状态异常需要有清晰提示和后台处理路径。
5. **高需求可升级人工服务**：AI 不能解决的导师意见、格式细节、修改诉求，可提交人工论文辅导服务申请。

## 5. 核心商业闭环

```text
访问首页/落地页
  → 注册/登录
  → 输入论文要求或选择论文类型
  → 充值/购买生成额度
  → AI 生成论文初稿内容
  → 保存生成结果
  → 合稿与格式调整
  → 导出 DOCX / Word
  → 提交人工服务申请（可选）
  → 后台人工处理服务需求
  → 用户查看服务状态或结果
```

商业闭环的关键不是一次性铺满所有论文服务能力，而是证明：

- 用户能被首页价值主张转化；
- 用户愿意为生成额度付费；
- 付费后能拿到可保存、可编辑、可导出的内容；
- 高意愿用户能通过人工服务入口进入更高客单价服务。

## 6. 一期必须保留的产品能力

1. 用户注册登录。
2. 个人中心与“我的论文 / 我的任务”。
3. 脑细胞 / 额度 / credit 账户。
4. 支付充值与订单状态。
5. AI 论文内容生成与结果保存。
6. 轻量合稿与格式调整。
7. DOCX / Word 导出。
8. 人工服务申请入口。
9. 后台基础处理入口。
10. 上线前基础验收、支付风险、生成失败处理、额度扣减一致性检查。

## 7. 当前产品不再追求的大而全方向

一期市场 MVP 暂不追求以下“大而全”方向：

- OnlyOffice 在线 Word 深度协同编辑；
- 完整写手公共任务池、抢单、接单、复杂反馈闭环；
- 完整机构端批量录入、机构代下单、机构协同交付；
- 全国高校基础数据全量同步；
- 多模型 Agent / Skill / MCP 工作流编排；
- 复杂论文全生命周期状态机；
- 复杂运营后台配置项；
- 大规模内容模板市场；
- 过细阶段性任务流转。

这些方向并非永久放弃，而是从一期市场发行版主线中移出，避免继续稀释“学生付费生成初稿并导出 Word”的核心验证目标。
