# 01 一期 MVP 用户角色与流程

> 当前有效性：本文档重新定义一期市场 MVP 的角色体系。旧文档中的机构、写手、复杂导师、渠道角色可作为后续版本参考，但不进入一期主流程。

## 1. 一期 MVP 角色总览

| 角色 | 一期定位 | 是否进入 MVP 主流程 |
|---|---|---|
| 游客 | 访问首页/落地页、了解产品价值、准备注册的潜在用户。 | 是 |
| 学生用户 | 已注册登录，可填写论文要求、查看生成入口、查看个人中心。 | 是 |
| 付费用户 | 已充值或拥有额度，可生成、保存、合稿、导出、申请人工服务。 | 是 |
| 平台管理员 / 运营人员 | 处理订单、支付、额度、用户服务申请等基础后台事项。 | 是 |
| 人工服务处理人员 | 处理用户提交的人工论文辅导服务需求。 | 是 |
| 机构用户 | 机构批量录入、代下单、协同交付。 | 否，后续版本 |
| 写手 / 公共任务池人员 | 抢单、接单、多轮交付反馈。 | 否，后续版本 |
| 渠道 / 合作方 | 渠道推广、分润、批量线索。 | 否，后续版本 |
| 复杂导师角色 | 导师在线协同、逐阶段评审、复杂修改闭环。 | 否，后续版本 |

## 2. 角色说明、核心目标与 MVP 操作路径

| 角色 | 角色说明 | 核心目标 | MVP 中的操作路径 |
|---|---|---|---|
| 游客 | 未登录访问产品页面的人。 | 判断产品是否能解决“论文初稿启动难、格式整理麻烦、需要 Word 交付”的问题。 | 访问首页/落地页 → 查看产品能力、价格/额度说明、合规提示 → 点击注册/登录。 |
| 学生用户 | 已注册登录但不一定有额度。 | 填写论文要求、理解生成类型、完成充值或购买额度。 | 登录 → 进入输入论文要求页面 → 选择生成类型 → 若额度不足进入充值/支付 → 返回生成入口。 |
| 付费用户 | 已拥有可用脑细胞/额度的学生。 | 生成可保存内容，合稿调整并导出 Word，必要时申请人工服务。 | 选择论文类型/输入要求 → AI 生成 → 保存结果 → 进入我的论文/任务 → 合稿与格式调整 → 导出 DOCX/Word → 提交人工服务申请（可选） → 查看服务状态。 |
| 平台管理员 / 运营人员 | 内部后台使用者。 | 保障支付、订单、额度、生成失败和服务需求可被处理。 | 登录后台 → 查看用户/订单/支付/额度状态 → 查看人工服务申请 → 标记处理状态或分配人工处理。 |
| 人工服务处理人员 | 内部处理人工论文辅导需求的人。 | 接收服务申请，理解用户需求，更新处理状态并交付处理结果。 | 登录后台或处理入口 → 查看待处理申请 → 查看用户提交资料和生成结果 → 更新状态 → 回传处理说明或交付物。 |

## 3. 一期核心流程

### 3.1 游客转注册

```text
访问首页/落地页 → 理解 AI 初稿生成与 Word 导出价值 → 查看合规边界 → 注册/登录
```

### 3.2 学生用户转付费

```text
登录 → 输入论文要求 → 选择生成类型 → 检查额度 → 额度不足 → 充值/购买额度 → 支付成功 → 返回生成
```

### 3.3 付费用户完成核心交付

```text
生成论文内容 → 保存结果 → 我的论文/我的任务 → 合稿与格式调整 → 导出 DOCX/Word → 下载或继续修改
```

### 3.4 人工服务升级

```text
用户提出人工辅导需求 → 提交服务申请 → 后台查看 → 人工处理 → 更新状态 → 用户查看服务状态或结果
```

### 3.5 后台运营兜底

```text
后台查看订单/支付/额度/生成记录/服务申请 → 定位异常 → 人工处理或备注 → 用户侧状态更新
```

## 4. 一期不做的角色能力

| 后续角色/能力 | 一期不做内容 | 暂缓原因 |
|---|---|---|
| 机构用户 | 批量录入、机构代下单、机构独立工作台、机构交付协同。 | 会显著增加权限、订单归属、数据隔离和运营复杂度。 |
| 写手 / 公共任务池 | 写手抢单、接单、阶段反馈、评价、结算。 | 一期以后台人工兜底即可，不建设平台型供给侧系统。 |
| 渠道 / 合作方 | 渠道分润、渠道订单池、合作方结算。 | 当前需先验证学生自助付费链路。 |
| 复杂导师角色 | 导师在线批注、多轮评审、逐阶段状态流转。 | 可通过人工服务申请和后台处理轻量承接。 |
| 多级管理员 | 复杂权限、审计、运营配置中心。 | 一期只保留基础后台处理入口，避免后台先行膨胀。 |

## 5. 角色设计原则

1. 一期角色必须服务市场付费闭环，不为未来复杂平台能力提前堆角色。
2. 学生用户与付费用户是主线，后台与人工服务是兜底。
3. 机构、写手、渠道、复杂导师可以在后续版本恢复，但必须基于一期付费和交付数据再评估。
